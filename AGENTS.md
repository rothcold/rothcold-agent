# rothcold-agent

- When designing or restyling UI elements, use the color roles and foreground/background pairs in [COLORS.md](COLORS.md).
- Use `main` as the default branch. Before v1.0.0, tag releases on `main`; do not create release branches.

- Keep the standalone Rust server in `server/`, the Python Hermes adapter only in `hermes-adapter/rothcold_agent/`, and React + TypeScript in `web/`. Build the API binary, `LICENSE`, and the adapter wheel in `dist/` via `script/build`; build the standalone web assets and notices in `web/dist/` with `script/pnpm build`, and run the web process with `script/pnpm start`. A standalone web stage keeps `web/default-web-config.json` beside `web/server.mjs`. Neither the API build nor its runtime uses web assets. Only `server/` opens the workspace database or listens on 8766. Keep build/test scripts in `script/` and test processes and fixtures in `tests/`.
- Check the pinned Hermes adapter contract listed in `README.md` before changing admission or delivery. Do not inspect the owner's Hermes profile, credentials, or history.
- Use Node 24.13.0 and `script/pnpm install --frozen-lockfile --ignore-scripts` (pnpm 10.33.0). Use `script/uv lock --check --no-build` with uv 0.13.9. Use the Hermes venv interpreter, not its repo Python pin or the system launcher. Never sync or install into the host venv.
- Run `SCREENSHOTS=1 script/test` and `script/test-gateway`. Both build the Rust binary with Cargo.lock and the adapter-only wheel. Stage only verified wheel files. Preserve automatic SQLite schema upgrades through v3 (`turn_updates`), v4 (`device_sessions`), v5 (`attachments`, `identities`, `backend_profiles`), v6 (`thread_title_jobs`), and v7 (archive flags and Inbox previews), and preserve the adapter HTTP contract (`/adapter/connect`, `/adapter/claim`, `/adapter/admission`, `/adapter/update`, `/adapter/push`, `/adapter/final`, `/adapter/profile`, `/adapter/avatar`, `/adapter/attachments/{id}`). `script/test` stages the verified wheel and typed Noise test client for the pinned Python/Hermes suite and invokes `script/test-web`. Keep the short `/proc/<pid>/cwd` Chromium fixture path and use a separate network namespace for the second workspace on Linux. Keep TLS test certificates and trust in the disposable test home. Do not replace the Gateway smoke's loopback-only namespace with a live-profile or unisolated run.
- Keep the iPhone app in `mobile/ios/` (SwiftUI, iOS 26.0 minimum) and shared product rules in `mobile/core/` (Rust via UniFFI). Generate Swift bindings and statically link the SDK-specific archive with `script/ios-core`; do not commit generated bindings or Xcode user data. The earlier [HTTPS M0 runbook](docs/ios-m0-runbook.md) is historical and requires the pre-Noise server. Use `script/test-ios` and `script/ios-build` on Apple silicon for native build validation. Native v1 must independently verify the Noise responder pin, and persist only the scoped device credential in a non-synchronizing, device-only Keychain entry bound to endpoint and pin. Do not use hosted devices or production credentials.
- Follow [ADR 0002](docs/adr/0002-noise-client-transport.md) and the [iOS delivery plan](docs/ios-first-plan.md) for the target: all Web/native business operations and file bytes use Noise, with no business HTTP fallback; `/adapter/*` stays separate on loopback. The normal server and the [Web](docs/noise-web.md) and [iPhone](docs/noise-ios.md) clients implement the [v1 contract](docs/noise-client-contract.md). This is not release acceptance or deployment approval.
- Run `script/test-noise` for the normal-binary client contract and the separate [development regression slice](docs/noise-dev-runbook.md). Keep fixtures loopback-only with a disposable workspace, out-of-band public pin and synthetic credentials. This is not a deployment or a Web/iOS acceptance test.
- Keep the adapter listener on literal `127.0.0.1:8766` with unchanged Host, Origin and independent bearer. Native Noise defaults to loopback and may explicitly bind a private interface behind ACLs. Keep the optional browser backend on loopback with exact configured Host and Origin, private WSS ingress and non-extractable browser key proofs. No HTTP client fallback or bearer in browser state. Keep device sessions persistent, expiring, revocable, and responder-scoped; store only credential hashes. Queue offline turns durably. Claim one per thread until its correlated final commits or the owner explicitly releases that `unknown` turn by ID. Never replay an uncertain claim. Keep late finals on their original turn. Only live owner approval decisions bypass the FIFO. Bind each to the displayed Hermes request, enforce its choices and authority, and never persist or replay the decision for delivery.
- Keep Settings in the top bar. Inbox and Settings span the main panel without a Categories column; use the current category and thread names for breadcrumbs.
- Keep Appearance in Settings and browser-local (System / Light / Dark). Let CSS follow the system in System mode; restore explicit preferences from the same-origin theme script before the first paint, on the connection and login pages as well as in the workspace. Keep CSP unchanged. Check computed role-pair contrast and Chromium screenshots in both schemes.
- Categories organize threads locally; keep the persisted `channel` field. Create a thread and reserve its first message in one transaction, without requiring a title. Thread renames update `chats.title` and cancel only that thread’s unfinished automatic title job; moves update only the current `placement.channel`; keep bookmarks, workspace navigation, composer drafts and DM routing keyed by stable IDs. Categories show a directory and a new-thread composer, not a conversation. At every width a selected thread replaces the category list in the main area and shows only the reply composer. Test switches from the desktop sidebar, mobile drawer, category list, search, inbox and thread hashes; check category scroll and focus on Back. Commit the final and its inbox entry together; do not backfill notifications or mark them read on GET. Automatic read receipts name only replies seen in the foreground; reserve whole-thread reads for the explicit button. Browser alerts must not replay the initial inbox. Test upgrades with synthetic databases only.
- Keep category and thread archive flags independent and `general` always active, even when renamed. Omit effectively archived entries from default lists and search, not ID links or Inbox. Never cancel existing turns or decisions upon archive. Create previews only for actual final or push notifications; never expose them in system alerts.
- Automatic thread titles use only the new thread’s opening text and the pinned Hermes `title_generation` auxiliary route. Keep title jobs separate from turn claims, bounded, single-use, without tools or notifications. Never title legacy or attachment-only threads, and honor a manual rename even when it repeats the temporary title. Test the real model request only with the isolated Gateway fixture.
- Keep TipTap composer styles in `web/app.css`, not injected at runtime. Enter sends unless an IME is composing or the slash menu is open; Ctrl+Enter and Shift+Enter add a line break. Slash selection only replaces the draft text. Keep approval suggestions bound to the same existing prompt and supported choices as a manually typed draft. Use Chromium tests to check Markdown serialization, slash keyboard/mouse/touch/IME behavior and draft restoration. Wait for an editable composer before typing; for a lost send receipt, drop the tunnel only after the independent Noise observer confirms the commit.
- Keep `/adapter/slash-catalog` ancillary to delivery and Noise `SlashCatalog` device-authenticated. Discover the pinned Gateway `/commands` directory (including platform skill and DM access filtering) on the adapter. Publish only bounded command/skill names. Keep the latest catalog in memory on its own API, expire it, and never show one backend’s results on another. Test the directory and explicit invocation against a synthetic skill in the isolated real Gateway.
- Keep attachment bytes private under the data directory, never at user-supplied paths. Enqueue links at most eight staged turn files atomically. Serve only recognized raster images and supported audio/video inline; serve HTML, SVG and arbitrary files as downloads. Web/native media bytes travel only through authenticated Noise file transfers, with no HTTP URL. Bound attachment transfers at both listeners. Noise `SyncProfile` and the live adapter must be bounded, correlated by sync ID, and never replace a newer manual edit; passive profiles fill empty agent fields only. Test with synthetic profile metadata and assets, including browser move, profile and attachment screenshots.
- Update this file and the runbook when meaningful changes affect the project, its tests, or the installed Hermes contract.
