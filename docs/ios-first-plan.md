# iOS 原生客户端交付计划

状态：当前 Web 与 iPhone 代码已接入 [Noise v1](noise-client-contract.md)，分别见 [Web 运行手册](noise-web.md)和 [iPhone 运行手册](noise-ios.md)。M0 的私网 HTTPS 和 `/api/*` 只适用于迁移前快照，已不兼容当前服务器。[历史 M0 手册](ios-m0-runbook.md)只记录旧路径。实现与单项测试不等于发布；隔离 Linux 回归及物理 iPhone 检查单独记录。

先交付一个能在 iPhone 上从私网登录、发消息并收到回复的客户端，再补齐 Web 的审批、收件箱、附件与管理功能。交付的是相同的消息语义，不是桌面界面的缩小版。Android 在此期间继续用响应式 Web。

本计划沿用 [ADR 0001](adr/0001-mobile-native-stack.md) 的 Swift + SwiftUI 和先 iOS 后 Android 路线。每做通一条 iOS 路径，就把其中已验证、与操作系统无关的规则放入 Rust，不等 Android 开工，也不先做一套 SDK。客户端业务传输以已接受的 [ADR 0002](adr/0002-noise-client-transport.md) 为准：iOS 原生直连 Noise，Web 通过二进制 WebSocket 记录连接 Noise；当前不保留客户端业务 HTTP、HTTP-in-Noise 或回退。

## 共享什么，什么不共享

| 归属                       | 职责与边界 |
| :------------------------- | :--------- |
| `mobile/core/`（M0 已建）     | 独立 Rust crate。按功能加入实际使用的协议类型、目录筛选、普通发送的请求标识与重试判定、回合状态解释、审批选择和已读判定。输入是服务端快照或平台事件，输出是值或待执行动作；不保存凭据，不推进服务端队列。 |
| `mobile/ios/`（M0 已建）      | SwiftUI 导航、原生输入与选区、前后台及可见性事件、定时与轮询、平台信任与 Keychain、私有文件、媒体和无障碍。当前用 Network.framework 直连，在提交凭据前用共享 Rust codec 验证 Noise 服务身份，设备授权独立办理。Swift 执行 Rust 返回的业务动作，不再写第二套业务规则。 |
| `server/`（已有）          | 仍是会话、队列、回合、审批权限和已读状态的权威。手机不经 Web 代理，不碰 `/adapter/*`、服务端数据库或 Hermes 配置。当前走原生直连 Noise。 |
| `mobile/android/`（以后）  | 交互与契约稳定后再建 Kotlin + Compose 工程。消费同一份 Rust 核心，替换网络、凭据、生命周期、输入和播放器，不移植 SwiftUI。 |

Rust 通过 UniFFI 向平台提供小而有类型的业务接口。第一个接口是「完整目录 → 活动分类和线程」，用父分类归档的用例证明 Swift 调用的不是空壳。后续业务规则不把网络客户端、文件句柄、媒体字节或视图对象当作输入；Noise 的连接与文件数据边界随协议实现评审。Markdown 先用 Web 样例确定支持的语法和链接规则；需要自写解析时放在 Rust，排版、选择和复制始终留在平台。

## 交付顺序与验收

下表为各阶段的功能和验收标准，不是通过声明。当前 [服务端契约](noise-client-contract.md)列出身份、目录、文件与授权边界；目录或首条文件往返成功不等于完成整个界面。M1 是首次消息试用，M4 是 iOS 首版候选。放行仍须对照 Web 和 iOS 行为，确认没有客户端 HTTP 和回退，并验证环回 adapter 契约。

| 阶段 | 用户能做什么 | 通过条件 |
| :--- | :----------- | :------- |
| M0 接入与共享核心 | 连接指定的私网地址，独立校验 Noise responder pin，再核对服务标识和版本后登录；重新打开 App 能恢复会话，看到 Rust 筛选出的活动目录。 | 用合成工作区验证真实的「Swift → Rust → Swift」路径；错误 pin、身份变化和不支持的协议不发送凭据，也不回退 HTTP。模拟器与真机分别验证绑定及 Keychain。 |
| M1 文本消息闭环 | 从分类目录用第一条消息创建线程；在线程里回复、读进度、阶段性文本和最终 Markdown，复制代码块。切线程保留草稿，返回恢复目录位置。 | 新线程和首条消息在同一事务保存，无需先取标题。丢失普通发送回执后以原请求重试，不新增消息。断开 Hermes 后同一线程连发两条，恢复后按顺序处理；断开手机网络则保留未确认状态。自动标题刷新不打断阅读或草稿。 |
| M2 审批、恢复与收件箱 | 查看命令并允许一次、允许本会话或拒绝；对指定 `unknown` 回合确认「停止等待」；从收件箱预览定位回复，支持逐条及显式整线程已读。 | 用两张同时打开的审批卡验证不会答错卡；断连不重放。迟到的 final 回到原回合。滚出屏幕、打开遮挡层或退后台均不误报已读；首次加载不补发旧提醒。 |
| M3 输入与附件 | 原生多行 Markdown 编辑，支持粘贴、换行与中文 IME。从 `/` 目录选 Commands 或 Skills 填入草稿。新线程和回复均可只发附件；可预览图片、拖动音视频播放进度、下载文件。 | 真机上确认中文候选词不发送，选命令也不发送；目录不可用时仍可手输。验证 8 个附件、超限、传输繁忙、断连清理，以及用 Noise 收到的文件播放或仅下载，见下文。 |
| M4 工作区管理与首版验收 | 创建、改名、归档和恢复分类；线程可改名、移动、归档和恢复。按分类名、线程标题搜索，不搜消息正文。设置提供资料与头像、从后端同步、设备会话与撤销、退出、切服、跟随系统／浅色／深色。 | 移动和改名不改变线程 ID、草稿或收件箱目标。`general` 可改名不可归档。归档线程或其父分类后，线程从活动目录和搜索消失，按 ID 和从收件箱仍可阅读；归档不取消在途消息或实时审批。资料同步冲突不覆盖较新的手工修改。完成下列真机和回归检查。 |

## 最容易做错的四条路径

1. 发送与断网。[现有 Web 请求模型](../web/chat.ts)区分草稿和服务端回合。目标保留原子创建线程和首条消息的语义。Rust 为一次普通发送保留请求 UUID、目标、文本和有序附件 ID；回执丢失时只以原内容重试，改了内容作为新请求，请求冲突不当作成功。收到排队回执不代表 Hermes 已执行。手机连不上服务时保留本地草稿或待核对请求，不设自动后台发件箱。服务端的 `queued`、`reserved`、`accepted`、`unknown`、`released`、`answered` 按原状态展示；`unknown` 阻塞同线程后续消息，不阻塞其他线程。只有用户确认才放行指定回合，不是取消或重发。
2. 实时审批与 `/`。按钮只展示当前回合更新提供的 `choices`。提交 `DecideApproval` 时携带所见卡片的更新 ID，不建普通队列项。手输或补全审批从开始输入时就绑定唯一可选卡；多张卡时用卡片按钮。过期、切服或重连后重新获取卡片，绝不保存或重试决定。[命令目录](../web/composer-slash-menu.tsx)只取自当前服务，只填草稿，不缓存到其他服务。
3. 前台轮询与已读。回到前台拉取目录、当前线程和收件箱；切页或切服时丢弃旧请求的结果。读取数据和打开线程本身不算已读。参照 [Web 可见性规则](../web/reply-attention.tsx)，Swift 报告前台、遮挡、回复可见及时间；Rust 只为连续可见满 600 ms 的那条回复产生回执动作。整线程已读必须显式点击。首轮收件箱是提醒基线；前台新提醒可关闭，只提示有新消息，不带正文或预览。锁屏及挂起时不承诺实时到达。
4. 身份与文件。只在验证 Noise 服务身份后登录或恢复授权；Keychain 项绑定选定地址和已验证 pin。owner token 不持久化，日志不记凭据，设备会话失效时回到登录。切服清掉未发送草稿、附件引用和旧页面，不等于撤销旧设备会话。按 ADR 0002 在 Noise 上分块上传完整内容，取得已完成文件 ID 后再发消息；限制每条消息 8 个文件、普通附件 25 MiB、位图头像 5 MiB，并保留传输槽与繁忙重试。验证同样经 Noise 下载的内容可播放和拖动；如需本地缓存则用受控私有临时文件并清理，不以 HTTP Range 或 URL 传凭据。HTML、SVG 和其他非媒体文件只下载。

## 测试、发布与 Android 交接

- Rust 契约测试使用合成的业务请求与响应。同一组样例覆盖父子归档组合、普通请求重试、审批过期、迟到 final、可见 599/600 ms 和中途遮挡。用现有 [Markdown 测试](../web/markdown.test.mjs) 对齐表格、列表、代码、引用及安全链接，不执行原始 HTML，只允许 HTTP(S) 链接。
- 当前集成测试用真正的 Rust Noise 服务与合成工作区，覆盖两端身份验证、目录和文件往返；用两个不同服务身份验证不串会话、草稿、目录或附件。Gateway 场景只用仓库已有的隔离夹具。真机走私网测试入口，不接所有者的生产服务、资料或历史；验收不等于批准部署。
- 在 macOS 固定 Xcode、Rust、UniFFI 及绑定生成工具，记录最低 iOS 版本和本地构建步骤。移动构建、核心测试与 iOS 测试各有独立脚本入口，不改变现有 `script/build` 和 Web 产物。在支持仓库隔离环境的 Linux 上保留 `SCREENSHOTS=1 script/test`、`script/test-gateway` 作为发布回归，不在 Mac 上用真实 Gateway 替代。
- 首版放行前，保留小屏和常规 iPhone 的明暗截图；检查登录、长对话、键盘、审批、收件箱和媒体页。按 [COLORS.md](../COLORS.md) 核对文字对比度至少 4.5:1、关键控件边界至少 3:1；真机检查大字号、VoiceOver、中文输入、Noise 服务身份和播放；私有 CA 检查适用于使用私有 CA 的 Web HTTPS/WSS；原生 TCP 仍独立校验 Noise pin。用同一合成工作区对照 Web 的最终消息数、归档状态和已读结果，不以静态截图代替行为测试。
- Android 启动条件：iOS 首版通过以上验收，核心能独立测试，接口和样例已随代码入库。在写 Compose 页面前，用生成的 Kotlin 绑定跑与 Swift 相同的目录和重试样例；若仍需重写规则，先修核心边界。在此之前不立 Android App 工程，不以两端 UI 齐备作为 iOS 发布条件。

## 需拍板的范围

- M0 最低版本为 iOS 26.0；采用本地 Xcode 签名，在所有者指定的 iPhone 上试用。不把商店发布作为 M1 前提。[运行手册](noise-ios.md)给出一次性模拟器步骤；物理 iPhone 安装与验收需另外授权，不能以模拟器替代。
- M1 前确认缓存范围。建议首版只在 App 私有目录保存当前服务的普通草稿及核对发送所需的最少数据，历史与列表按需拉取；不建完整离线数据库。注销时清理该会话私有数据。
- M2 前单独评审是否需要后台提醒。默认仅做前台轮询，不引入 APNs、外部中转或正文推送。系统分享扩展放在首版之后；首版只要求从 App 内选择文件。这两项不阻塞消息闭环。
