# Rothcold Noise client contract v1

The normal server executable implements this contract. It does not serve client HTTP or media URLs. Both repository clients implement it; see the [Web](noise-web.md) and [iPhone](noise-ios.md) wiring guides. This contract is not a release or deployment approval.

## Authoritative implementation

- [Shared Rust crate](../server/noise-protocol/Cargo.toml), [`v1.rs`](../server/noise-protocol/src/v1.rs): requests, replies, typed results, client handshake, proof bytes and result reader. [`lib.rs`](../server/noise-protocol/src/lib.rs) implements the common record codec. Dev exports outside `v1` are **not** production protocol.
- [Service/connector](../server/src/noise.rs), [identity](../server/src/noise/identity.rs), [device authorization](../server/src/noise/auth.rs), [workspace](../server/src/noise/workspace.rs), [files](../server/src/noise/transfer.rs). The [fixture client](../tests/noise_fixture_client.rs) is a minimal reference for native framing and reply sequencing, not a UI/product client.
- The crate can be built for `wasm32-unknown-unknown` with `getrandom`'s `wasm_js` backend (`wasm-bindgen`, Web Crypto secure randomness) and `aarch64-apple-ios`. The Web and iPhone clients provide their own thin browser and Swift/UniFFI bindings and network I/O. No fallback RNG and no old `noise-dev` or HTTP fallback.

## Connect and verify

| Connector | Wire | Ingress |
|---|---|---|
| Native | TCP to the configured address; unsigned two-byte big-endian length (1–65,535) followed by exactly one Noise packet | Loopback by default; operator may bind an explicit private IP. No HTTP, TLS or DNS trust substitution. |
| Browser | WSS via the operator's trusted private HTTPS site or reverse proxy. Exactly one binary WebSocket message per Noise packet, no TCP length prefix | Upgrade only at `/noise`; exact `Host` and HTTPS page `Origin`. No missing or `null` Origin, query, cookies, authorization header, subprotocol or application data in the upgrade. No text frames or negotiated extensions. |

`Noise_NK_25519_ChaChaPoly_BLAKE2s`, Snow with the RustCrypto resolver, fixed ASCII prologue `rothcold-agent/noise/1`. Both handshake packets are exactly 48 bytes with empty payloads. Bind to the **32-byte X25519 responder public key** supplied independently by the operator; the client must never get the pin from this socket, TLS alone, an unauthenticated discovery result, or first use. Use `Initiator::start(pin)` then `verify(reply)`; only the `VerifiedClient` can create app requests. An address or advertised service name is not authorization. Pin mismatch or handshake/record failure closes the connection; do not send credentials or try another protocol. Pin changes require explicit re-verification and enrollment, not automatic retry.

## Enrollment and device authorization

- `Status` is available after pin verification, without device authorization. `LoginNative` submits the existing owner secret (32–512 printable ASCII characters, no spaces) and a device label (trimmed, 1–80 characters, no control characters). The typed `NativeLogin` returns the verified pin, a random 32-byte credential and the device. Persist **only** the device credential scoped to this selected endpoint and verified pin in the native device-only, non-synchronizing Keychain entry. Restore with `ResumeNative` only if the stored pin equals the independently configured pin; the codec enforces equality against the verified link. Never migrate an HTTP token or cookie, persist the owner secret, or include any secret in a URL, argv, or logs.
- Browser enrollment uses `crypto.subtle.generateKey({name:'ECDSA', namedCurve:'P-256'}, false, ['sign','verify'])`. Export only the public key in raw uncompressed SEC1 format (`04 || x[32] || y[32]`), never the private key. `RegisterBrowser` sends the public key, device label, owner secret and proof inside the verified Noise channel. It returns `Device`, **no bearer**. Discard the transient owner input. Store the non-extractable signing `CryptoKey` by structured clone in IndexedDB scoped to the trusted static site's origin, connector selection and verified pin, along with public key and device ID. Never serialize a private key or store/export a bearer. Fail closed if the browser cannot preserve the `CryptoKey`; no localStorage, cookie, or software-key fallback. Revoking the device is server-side; clearing local state alone does not revoke it.
- `ResumeBrowser` signs a **fresh** proof for the current handshake. Sign `VerifiedClient::browser_proof(registering, id, public_key)` with Web Crypto `ECDSA` / `SHA-256` returning fixed 64-byte `r || s` (not ASN.1 DER). The exact bytes are ASCII `rothcold-agent/noise/1/browser-proof` plus NUL, responder pin `[32]`, final Noise handshake hash `[32]`, a one-byte operation (`1` register, `0` restore), raw key `[65]`, then the literal lowercase device UUID UTF‑8 (`0` bytes at registration). Browser key proof is connector-specific; native bearer cannot authorize in WS, and browser proof cannot authorize in TCP. A valid signature proves key possession, not hardware backing or safe page code. Malicious code at the trusted static origin can ask the non-extractable key to sign: maintain site/TLS integrity and origin isolation.
- The server retains only domain-separated, responder-scoped credential hashes and device metadata in SQLite, expires devices after 30 days, and rechecks devices at every business request and file step. `Logout` revokes the submitted device; `RevokeDevice` revokes by device ID, even on another open connection. Close an unauthorized/revoked connection and create a fresh verified connection for re-enrollment. Pre-cutover HTTP sessions are not restorable via Noise. Same owner authority as before: authorized devices can manage all workspace operations and other device sessions. Adapter credentials are never accepted for device enrollment.
- If an enrollment receipt is lost, it may have committed. Don't blindly retry; enroll a new device (new browser key) and revoke the orphan by label and ID. Endpoints don't auto-reconnect or replay mutations.

## Requests, responses and files

After handshake, use Snow in normal ordered transport mode. A record's plaintext begins with `0` then one UTF‑8 JSON object, or `1` then big-endian `u32` sequence plus **1–32,768 raw bytes**. Noise contributes a 16-byte tag; ciphertext must not exceed 65,535 bytes. JSON message types and discriminator values are in `v1.rs`; fields are snake_case, `Key` and signature bytes are arrays of unsigned bytes. A malformed record or out-of-phase message closes the link; application validation yields a typed `Error { code, message }`. Branch on `code`, not the human message. `busy` and `rate_limited` permit deliberate retry after backoff where safe; `invalid`, `unauthorized`, `missing`, `limit`, `conflict` and `storage` aren't success receipts.

One in-flight operation per connection; no pipelining. For non-file operations receive `ResultStart { size }`, sequential chunks starting at zero (full 32,768 except final), then `ResultComplete`. Concatenate **only** for results bounded to 512 KiB, and decode one typed `Outcome` only after the terminal record (`ResultReader` verifies size and ordering). Do not expose intermediate bytes. A call may yield `Error` instead of a result. A lost response does not mean a mutation failed; only re-use the same turn UUID with identical input when deliberately retrying an enqueue, with `fresh=false` indicating an existing durable reservation. Approvals are never enqueued or replayed, and uncertain adapter claims require explicit `ReleaseTurn` by original ID; late finals stay attached to that ID.

Directory reads use `Categories` and `Threads`; request both with `include_archived=true` for the complete directory, then join by stable channel ID. Archive flags are independent and effective archive derives from thread **or** parent. `History` pages turn text, state, answer and attachments; fetch `TurnUpdates` for each turn to load live progress/commentary and allowed approval choices. Updates and history remain accessible by ID for archived entries. `Inbox` does not mark on read; use `ReadReply` for seen items and `ReadThread` only for explicit whole-thread reads. For every paged call, start with absent/null `after`, then supply the returned `next` with the **same** scope/filter until `null`. Cursors are opaque decimal strings, not authorization; do not parse them as JavaScript numbers. Reads are live, not a multi-request snapshot; reload from the beginning to refresh changes. History and updates use one potentially large item per page; other pages use up to 16. Fetch profile backend pages separately from the identity/profile operation. Slash catalog may be null on expiry.

- **Upload:** `Upload` (`turn` ≤25 MiB, `avatar` ≤5 MiB) → `UploadReady` → send exactly one correctly numbered chunk and await matching `UploadChunkAccepted` before the next → `UploadFinish` → `UploadComplete { attachment }`. Cancel while receiving bytes with `UploadCancel` → `UploadCancelled`, or close; do not send anything after `UploadFinish` before its receipt. A committed upload whose receipt is lost may remain staged. Ordinary files become turn attachments only on an authorized committed turn enqueue (≤8). Avatar selection is a separate identity patch: omit `avatar` to keep it, use `{ "type": "clear" }` to clear it or `{ "type": "set", "id": "…" }` to select it. Filename and optional MIME hint are untrusted; they never determine a server path. Local source read failure must close or explicitly cancel; do not finish a partial upload.
- **Download:** `Download { id }` → `DownloadStart { attachment }`, then one `DownloadNext` per chunk, validating fixed size and sequence. At advertised size send one more `DownloadNext` and await `DownloadComplete`. `DownloadCancel` → `DownloadCancelled`. Read to private temporary storage and expose only after terminal success with exact advertised bytes; discard partial content on errors/closure. Do not render `kind=file`, HTML or SVG inline. Only use the MIME/kind provided by the server for recognized raster, audio and video; use private Blob/object URLs or native local copies with their lifetime tied to authorization. Never use an HTTP range or a direct file URL.
- Two upload and eight download slots are shared with the loopback adapter; the server returns `busy` without queueing. Idle record timeout is 30 seconds, transfer deadline two minutes, absolute connection lifetime 20 minutes. On expiry/disconnect, reconnect intentionally with fresh transport and restore the same still-valid device; don't automatically replay in-flight mutations. Nonces are independent in each direction and not reset on the same connection. WebSocket, TCP or transfer framing errors must discard pending output.

## Operator runbook and disposable validation

Start with a private data directory (`0700`, owned by service account; use a private parent) and distinct owner/adapter environment secrets as described in the [project README](../README.md). From a trusted local shell as the service user run `ROTHCOLD_DATA_DIR=/private/workspace ./rothcold-agent noise-pin`. The only output is the lowercase 64-hex public pin. Convey it to each client over an authenticated **out-of-band** channel (for example, compare all hex at a trusted console). Verify both endpoint selection and pin; do not rely on automatic discovery. The private `noise-v1.identity` file is generated atomically by that local command and must be backed up and restored with the workspace. Normal startup fails if it is missing rather than generating a replacement. For key compromise/loss: stop the process, secure/rebuild the workspace, replace the identity only as a deliberate rotation, independently distribute the new pin and re-enroll clients. Old credentials are scoped to the old pin; do not keep an old compromised identity in service or import its sessions under the replacement. Use trusted backups and the product device list to revoke stale device rows.

Run the normal `rothcold-agent` executable with those same environment settings. Native binds `127.0.0.1:8768` by default (`ROTHCOLD_NOISE_NATIVE_BIND`). For native across LAN/VPN, choose one locally assigned IP in IPv4 RFC1918 / RFC6598 or IPv6 ULA, use an OS firewall/private VPN ACL restricting intended clients, and never expose to public ingress or NAT-forward a port. The adapter always binds **`127.0.0.1:8766`**, retaining literal `Host`, `Origin` and independent bearer. It must never be reverse-proxied. Serve a browser connector only after explicitly setting all three variables, e.g. `ROTHCOLD_NOISE_WS_BIND=127.0.0.1:8767`, `ROTHCOLD_NOISE_WS_HOST=connector.private.example:8443`, `ROTHCOLD_NOISE_WS_ORIGIN=https://workspace.private.example:8443`. A TLS ingress on a private network must verify/match its HTTP host, forward only the configured WebSocket upgrade route with unmodified `Origin` and binary frames. The [Web edge](noise-web.md) routes exact public `/noise/<configured-id>` to its fixed loopback destination, sending literal `GET /noise` and the configured Rust connector `Host`. For a direct ingress instead of the Web edge, match the public Host at ingress and forward only exact `GET /noise` with the Host configured on the Rust connector. Do not forward cookies or authorization; choose a cookie-free connector origin. No generic proxy or HTTP business routes. Use a browser-trusted matching certificate and trusted static site; use ingress header/time/connection limits and ACLs. The server caps both connectors at 24 concurrent handshakes/connections and 96 validated connection attempts per 10 seconds per connector, imposes a 5-second handshake deadline and limits failed owner sign-ins across the workspace to eight per minute. The browser backend is never directly reachable from the private network.

`script/test-noise` runs the regular executable against a private temporary workspace with synthetic credentials and OS-assigned native/WS loopback ports, exercises the shared codec and checks the browser/native compilation targets. It needs exclusive use of adapter port 8766 (use an isolated namespace where available; it fails if the bind is occupied). The WS test simulates the trusted proxy leg on loopback with synthetic Origin and Host, not TLS or a real browser. `script/test-gateway` uses the typed native fixture client against that same normal server executable and the pinned real Gateway in its original isolated namespace. It does not use an HTTP business route, a live owner profile, or a real model service. The opt-in [older development suite](noise-dev-runbook.md) is a separate regression probe. `script/test` composes the normal-binary, pinned adapter, and `script/test-web` suites; see the [regression inventory](README.md#regression-migration-inventory). The Rust WS smoke is not a substitute for real browser TLS or iPhone checks.

To exercise just the Gateway's typed fixture driver with the release executable and no Hermes, run from the repository root (adapter port 8766 must be free):

```sh
cargo build --locked --release --manifest-path server/Cargo.toml --bin rothcold-agent --example noise-fixture
python3 -B tests/noise_fixture_smoke.py server/target/release/rothcold-agent server/target/release/examples/noise-fixture
```
