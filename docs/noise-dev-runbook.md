# Noise 本地开发验证

这是 [ADR 0002](adr/0002-noise-client-transport.md) 的第一段端到端验证，不是可部署的入口、生产配对方案或 Web／iOS 的迁移验收。它不改变现有 HTTPS M0、Web HTTP 业务通道或 adapter。这个旧端点仍然只在测试目标中编译和启用；正常服务端二进制提供的是独立的 [Noise v1 生产协议](noise-client-contract.md)，不可混用。

## 运行

在仓库根目录运行 `cargo test --locked --manifest-path server/Cargo.toml --features noise-dev --bin rothcold-agent noise_dev::tests`（`script/test-noise` 也包含这组回归）。旧夹具需要 Rust/Cargo 与服务端的 SQLite 开发依赖，不需要 Node、Hermes、证书、任何真实凭据或正在运行的 API。测试自己绑定 `127.0.0.1` 的系统分配端口，每个夹具使用独立的临时数据目录和实际 SQLite schema。它不会读取 `ROTHCOLD_DATA_DIR`、占用 8766、连接现有实例或改动系统信任。所有文件和设备会话都是合成的。

## 这条路径验证了什么

- [Rust 参考客户端](../tests/noise_dev_client.rs) 使用真实二进制 WebSocket 连接 [Axum 端点](../server/src/noise_dev.rs)。HTTP 仅用于 `/noise` 升级：精确校验本地 Host；拒绝 Origin、Cookie、Authorization、查询与文本载荷。这个无 Origin 的本地端点**故意不支持浏览器**，不存在业务 HTTP 请求、HTTP 封装或 HTTP 回退。
- [共享 Rust 协议](../server/noise-protocol/src/lib.rs) 不依赖 WS、SQLite 或文件系统。锁定 Snow 0.10.0 的 RustCrypto resolver，套件为 `Noise_NK_25519_ChaChaPoly_BLAKE2s`；固定 `rothcold-agent/noise-dev/1` prologue 隔离这个实验的版本，无协商或降级。Cacophony 向量验证套件握手和首条密文，真实连接另外验证本实验的 prologue 和记录。夹具用系统随机源生成一次性服务端密钥，独立于 WS 把公开 pin 直接交给客户端；握手验证失败不发送凭据。
- 夹具为目标 pin 单独签发随机的 32 字节设备能力。参考客户端在握手后、序列化之前核对凭据绑定的 pin 与已验证的服务端身份，即便到另一台服务端的握手本身成功，也不向它提交凭据。SQLite 只保存与 HTTP 进行域隔离、绑定该 pin 的校验值，复用现有会话过期和删除撤销机制，没有运行时签发接口或 HTTP 登录引导。未认证时不得调用业务；继续使用已打开的连接仍须在每次业务请求和每个文件块上重新检查，上传提交前在持有数据库锁时复核。这个夹具不决定以后怎样签发、配对、保存、轮换或恢复密钥与凭据。
- 目录读取实际工作区中完整的分类／线程投影，保留归档状态；超过单条响应预算直接拒绝，不截断、不分页。记录含有版本隔离、带类型的控制字段及固定顺序的原始文件块。一条连接串行处理请求（最多 32 个）；最多 12 个已升级连接，每次收发最多等待 3 秒，连接最多 90 秒。文件块最多 32 KiB，带序号及认证标签的最大密文为 32,789 字节。
- 只处理普通回合附件：25 MiB 单文件上限，沿用共享的 2 个上传槽、8 个下载槽、文件名清理、类型识别和元数据存储。上传使用首块做类型识别，无 MIME 提示；不渲染或公开媒体 URL。私有临时文件接收完整的顺序块，校验写入和长度，提交实际附件行后才回传 ID。按 ID 读取已完成的普通附件同原 owner 的暂存读取语义；仅暂存不会向 adapter 授权。没有头像、回合提交、Range、续传、自动重试或产品媒体预览。
- 上传完成时，后台任务先准备私有文件的最终名称，不持有数据库锁做文件同步；随后在同一 SQLite 事务内复核授权、写入附件行并在提交前与取消竞争。取消或截止时间先到会回滚该行，后台任务在清理两个名称后释放上传槽；一旦进入 SQLite 提交阶段，连接中止不再回滚，成功提交的数据不会因客户端未收到回执而丢失。参考客户端遇到本地读取错误或长度不符会立即关闭连接，不能复用该连接。
- 两个参考客户端连接上传／下载同一个 98,321 字节文件（四个数据记录），比较客户端下载与磁盘内容的每个字节。覆盖错误 pin、无权／过期／撤销、超限、繁忙、篡改／重放／截断／乱序、部分文件不可读取、取消／断连／空闲、提交失败以及接收端下载不完整时的清理。启动清理测试模拟进程中断留下的文件系统状态，清除未提交暂存和悬挂的最终名称并保留已提交文件；不声称验证真实断电或进程 kill。若完整上传已提交但回执丢失，不能假定未提交或自动重放。

## 尚未验收

- **Web**：实际浏览器与安全同源 WSS、精确 Origin/后端范围、可信站点和 Noise pin 引导、独立会话凭据的取得／保管／恢复／切服、WASM 与随机源的目标验证、CSP、真实浏览器背压及安全预览／下载。共享 crate 现已为 v1 开启 `wasm32-unknown-unknown` 的 Web Crypto 随机源；这不证明浏览器产品集成。未改 CSP、Web proxy、媒体或 UI，也未跑浏览器 Noise 集成测试。
- **iOS**：原生连接器、Swift/UniFFI 接协议、系统及 Noise 身份信任边界与 Keychain、真实目录和文件交互、切服、模拟器与真机验证。共享协议 crate 的 `aarch64-apple-ios` 检查通过，不等于 iOS 集成。未改现有 M0，未跑 iOS Noise 集成测试。
- 未验收生产身份引导、轮换与恢复、头像和其他业务对齐、两个实际产品客户端互通、异常断电恢复、发布回归和 HTTP 移除。不要将这个端点接入部署，不要把已有 HTTP 客户端视作 Noise 回退。Gateway 继续走现有隔离测试；不以不隔离的 Gateway 运行替代。
