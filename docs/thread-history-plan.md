# Thread 历史：先显示最新消息，再向上加载

状态：第二阶段设计，尚未开发。第一阶段只为 Rust 服务端的 WebSocket 连接开启 `TCP_NODELAY`。当前客户端仍使用 [Noise v1 契约](noise-client-contract.md) 从旧到新分页，并逐轮读取更新。本文不是已上线的接口说明。

## 打开、滚动和发送

- 打开 Thread 时，先取最新一页。首屏锚定最新消息，页内仍按时间从旧到新排列。只要拿到这一页的消息正文、附件元数据和当前状态，就显示对话；不等旧页、全部进度记录、头像或附件字节。
- 到达顶部或选择「加载更早消息」时才请求上一页。把旧页插入顶部，保留原先第一条可见消息的位置和偏移。若用户正在读旧消息，新消息不抢滚动位置；提供返回最新位置的入口。
- 发送不依赖旧页加载。收到服务端的持久化回执后，用原请求 UUID 把自己的消息放进最新一页并显示为已排队，不等待整段历史重读，也不把排队说成 Hermes 已接收。回执丢失时显示「结果待确认」，重连后按 UUID 核对；不要自动重发。新消息、迟到的 final 和进度更新都合并到原 turn，不制造重复气泡。

## 服务端：稳定的最新页和旧页游标

1. 新增明确的 Noise 读取能力，不反转现有 `History.after` 的含义。尚未升级的 Web 或 iOS 仍能用 v1。先在共享 Rust 协议中定义请求、结果、能力标识和测试向量，再固定名称给客户端；不加业务 HTTP 回退。
2. 不带游标时读取最新一页；返回的 `older` 是本页最旧一项之前的排他游标，`null` 表示到头。按稳定的服务端插入顺序定位，不按设备时钟、标题或数组下标分页。游标作为不透明值使用，不跨工作区或 Thread 复用。翻页期间追加新 turn、修改旧 turn 或移动 Thread，已有边界不漂移。
3. 首版建议每页最多 20 轮，并受实际编码后的字节上限约束（现行 v1 每个结果最多 512 KiB）。大消息可以让一页少于 20 轮，不能静默截掉正文或跳过记录。分页方向是从新到旧，返回的每页固定为从旧到新。空 Thread 返回空页，无下一页。
4. 一次最新页请求给出渲染所需的 turn 投影，包含状态、已提交的 final 和附件描述，不内联附件字节。不要对没有更新的 turn 逐项发 `TurnUpdates` 才肯显示首屏。需要时再补取更新；当前待审批和 `unknown` 恢复操作必须从受权的最新状态获得，不能由缓存推断。
5. 向前翻页的 `older` 不兼作刷新游标。前台刷新只合并新增或变更的 turn；服务端须能报告旧 turn 的状态变化，包括迟到的 final，而不只是新插入的 UUID。变更位置不可继续时，明确要求重新获取最新页并使旧缓存失效。新动作优先于尚未发出的预取；已经发出的请求仍遵守 Noise 的串行与撤权规则。

## Web 与 iOS：先做会话内缓存

- 首版只缓存内存中的有限页，不落盘保存正文、附件字节、审批权限或令牌。缓存键包含所选端点、已验证的 responder pin、设备授权范围和稳定 Thread ID；Web 还要区分 backend 映射。每端设置总页数和字节预算，淘汰最久未使用的页。
- 同一有效授权连接内切回 Thread，先显示已缓存的最新页，再校验变更。用 turn UUID 去重并替换变更项。较慢的旧请求不能覆盖新状态；切换 Thread 后返回的旧响应不能写进新视图。不要把缓存中的审批选项当作可执行决定。
- 断线、授权失败、撤权、登出、切换端点或 pin 时，清空相应缓存并丢弃未完成的读取。恢复后先重新验证授权，再展示私有内容。iOS 进入后台或锁屏时清除内存中的敏感视图和预览。落盘或离线浏览不在本阶段内。
- 读取或预取历史不产生已读回执。仍只确认在前台实际可见、满足停留时间的回复；只有明确的整 Thread 已读操作可以批量清除未读。

## 交付顺序与验收

1. 服务端先行。 用合成的 0、1、48、128 轮 Thread 测首尾页、字节边界，以及翻页中新增消息、旧消息迟到 final 的情况。检查连续翻页无重无漏、新读能力的权限与 v1 一致、旧版 iOS 可继续连接。
2. Web 验收。 记录打开到最新消息可见、按 Enter 到自己的消息可见、首屏业务请求数，以及缓存命中后的刷新数；区分首次握手和复用连接。48/128 轮的首屏不能随总轮数逐轮发请求；在无更新、无附件的样例中，历史正文应由一次最新页读取提供。用 Chromium 验证滚动锚点、跨设备更新、请求竞态、未读、工作区隔离和撤权。使用同一环境与第一阶段对照；不把本机毫秒数写成跨设备承诺。
3. 交给 Mac 端。 服务端与 Web 通过后，在本文补上协议提交、能力标识、样例请求/回应及共用测试向量；登记实测结果后再通知 iOS 开发。iOS 从锁定的共享 Rust 类型更新 UniFFI/Swift 绑定，不照抄 Web 代码或另猜接口。按 [iPhone 手册](noise-ios.md) 在 Mac 上跑 `script/test-ios`、`script/ios-build` 和 Web/iPhone 联测；在真机补验快速切 Thread、向上翻页、后台恢复、撤权和滚动位置。
